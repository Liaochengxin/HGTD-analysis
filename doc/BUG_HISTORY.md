## BUG-20260914-01: IV 扫描循环越界读（Card52_v3.C）

- **commit**: （提交后回填 hash）
- **time**: 2026-09-14
- **影响文件**: `CQC/Card52_v3.C`

### 症状

2nd batch（95 片晶圆）IHEP 复算与 IME 官方结果的交叉核对中，8 个病态 sensor
（B23_9 s14、B23_15 s13、B31_1 s36/s48、B31_20 s3、B33_1 s37、B36_10 s13、
B36_22 s37，全部为开路/短路坏点）的数值出现无规律差异：

- `sensorYield.csv` 出现天文数字垃圾值（如 Vbd_Min = -2.8e110 V、6.6e8 V；
  IME 侧同款代码出现 -1.8e39）
- 出现初始哨兵值原样写入（I_Min = 10、I_Average = 0、I_Ratio = 0）
- 同一份代码、同一份数据，在不同机器上结果不同（未定义行为的指纹）

**分级不受影响**：8 个 sensor 两边一致判 C，其余 93 片晶圆 4836 个 sensor
全部变量逐位一致。

### 根因

`CQC/Card52_v3.C` 两处扫描循环写成：

```cpp
for(int j=1;(j<=N-1)&&(if_fi==0);j++){
    if ((-y[j] * 1e6 <= 15 * LCT) && (-y[j+1] * 1e6 > 15 * LCT)){
```

1. **越界读**：`j` 最大取 `N-1`，此时 `y[j+1]` = `y[N]`，越界一个元素。健康曲线
   在中途真实击穿后 `break` 提前退出，永远踩不到；**未击穿列（开路）被迫扫完
   全程**，最后一次迭代读到数组外的堆内存垃圾。垃圾字节恰好大于 7.5 µA 阈值时
   伪造出一次"击穿"，线性插值出荒谬的 Vbd；垃圾内容随机器/内存状态变化，导致
   "同代码同数据不同结果"。
2. **漏掉首对点的穿越**：循环从 `j=1` 起跳，第 0→1 点之间的真实穿越被跳过
   （极端短路列的场景）。
3. **下游污染链**：垃圾 Vbd 进入 `VbdCMin` 取最小 → `VProbe = 0.8×VbdCMin`
   失效（为负或低于首个采样电压 2 V）→ 漏电循环全部失配 → 哨兵值整行写入。
   实测案例：B31_20 s3 存档结果中 col 4 = 0.654 V 无法由交付数据重现
   （该列全程最大 0.15 µA，无任何穿越），为当次运行的异常产物。

### 修复

| 位置 | 修改 |
|---|---|
| 击穿扫描循环 | 上界 `j<=N-1` → `j<N-1`（消除越界读）；起点 `j=1` → `j=0`（补上首对点穿越） |
| 新增短路前置判断 | 首点电流已超阈值时直接记 Vbd = 首点电压（硬短路语义），不再落入兜底分支 |
| 漏电扫描循环 | 同样上界改 `j<N-1`、起点改 `j=0`（VProbe 低于 2 V 时也能插值） |
| 兜底分支 | 加 `N > 0` 守卫（空文件不再读 `x[-1]`） |
| `VbdColumn`/`LKGColumn` | 补 `= {{0}}` 初始化（消除未初始化内存） |
